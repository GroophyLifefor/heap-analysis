# Contributing

## Conventions

These are not style preferences. Every one of them exists because breaking it
produces a bug that looks correct in a diff.

### 1. Never hardcode a stride

`snapshot.meta.node_fields` and `edge_fields` describe how many integers each
node and edge occupies, and the list changes between V8 versions. A snapshot
written by one Node version can have a different field count than one written
by another (an older V8 writes an extra `trace_node_id` field on nodes, for
example). Code that assumes a fixed number instead of reading `meta` silently
decodes garbage on the other version, no error, just a wrong answer for every
field after the one that got dropped or added.

Read the stride from the snapshot. Always.

### 2. Three integer spaces address a node, never mix them

```
nodeIndex    ordinal, 0 .. nodeCount - 1        what our APIs take and return
nodeOffset   nodeIndex * nodeStride              what an edge's `to_node` holds
nodeId       V8's stable object id               what survives across snapshots
```

They are all plain numbers, so passing one where another is expected throws
nothing and returns a wrong answer. Name every variable and parameter after
the space it belongs to, and say which one in the JSDoc. Convert at the
boundary, never in the middle of a loop.

Public APIs take and return `nodeIndex`. `nodeOffset` stays inside the module
that reads the raw arrays. `nodeId` matters only where a snapshot has to be
compared against another one, since indexes are not stable across snapshots
but ids are.

### 3. Sizes are bytes

Everywhere, with no exceptions, all the way to the edge of the package.
Formatting into KB or MB happens only in `bin/`, at the moment of printing. A
function that returns "size" returns an integer number of bytes.

### 4. Anything per node or per edge is a typed array

`Int32Array`, not `Array`, and not an array of objects. A real snapshot holds
millions of nodes, and a boxed JS number per field is the difference between
analysing a heap and becoming the problem. Decode into a plain object only for
the handful of nodes a caller actually looks at.

### 5. Throw `HeapAnalysisError` subclasses

Never a bare `Error`, never a string. The CLI catches `HeapAnalysisError` and
prints it as a message, and lets anything else crash with a stack trace,
because anything else is a bug in this package rather than bad input.

Pass `{ cause }` when wrapping a lower-level error.

### 6. Snapshots are generated by tests, never committed

`test/helpers/fixture.js` gives you two options. `tinySnapshot()` is hand
written and small enough to verify by eye, use it for anything about decoding.
`withRealSnapshot()` writes a real one from the running process, use it to
check invariants that a hand written fixture would be too clean to catch.

No `.heapsnapshot` file ever enters git.

### 7. Zero runtime dependencies

`package.json` has no `dependencies` and the intent is to keep it that way.
Node's standard library covers what this package needs, including argument
parsing (`node:util`), testing (`node:test`), and taking snapshots
(`node:v8`). A dependency has to earn its way in by doing something the
standard library genuinely cannot.

### 8. Known limits are stated plainly, not hidden

Node cannot hold a string longer than roughly 537MB
(`buffer.constants.MAX_STRING_LENGTH`), and a snapshot from a large process
can exceed that. Until this package streams instead of reading a whole file
into memory, that case is caught and reported with a clear message rather
than left to surface as a raw V8 error.

## Working on it

```sh
npm test
```

`node --test`, no framework. Tests live next to what they test, named
`*.test.js`. Anything else under `test/` is a helper and is not discovered as
a test.

## Pull requests

One reviewable change per pull request. A pull request that changes behaviour
comes with the test that fails without it.
